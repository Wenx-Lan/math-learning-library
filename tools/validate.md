# 校验清单 · 高中数学学习资源库

本文件说明如何**自动自检**（`tools/selftest.html`）与如何做**人工验收**，用来在交付前确认 18 章数据文件全部合规、两个主界面都能正常工作。

数据格式的权威契约见 `docs/数据格式说明.md`；本文件只讲"怎么检查"。

---

## 一、必须用本地静态服务器打开（不能用 file://）

### 1. 启动方式（任选一种，在**仓库根目录**执行）

```bash
# 方式 A：Python（Windows / macOS / Linux 大多自带）
python -m http.server 8000
#   若提示找不到 python，试：py -m http.server 8000  或  python3 -m http.server 8000

# 方式 B：Node.js
npx serve -l 8000
#   或：npx http-server -p 8000
```

然后在浏览器访问：

| 页面 | 地址 |
| --- | --- |
| 站点首页 | <http://localhost:8000/index.html> |
| 数据自检页 | <http://localhost:8000/tools/selftest.html> |
| 基础知识第 1 章 | <http://localhost:8000/index.html#/knowledge/1> |

> 直接双击 `index.html` 打开时地址是 `file:///.../index.html`，**数据会加载失败**。
> 这不是代码 bug，而是浏览器安全策略导致的，属于预期行为。

### 2. 为什么 file:// 下必然失败

1. **`<script src>` 动态加载被拦。** 主程序 `js/app.js` 不预加载 18 章数据，而是按需创建
   `<script src="js/data/k-1-集合.js">` 再插入 `<head>`（见 `app.js` 的 `loadScript`）。
   在 `file://` 下，Chrome / Edge 会把 `file://` 视为**不透明来源（opaque origin）**，
   脚本请求会被 CORS 或本地文件策略拒绝，`script.onerror` 被触发 → 页面显示
   "数据文件缺失或加载失败"。
2. **各浏览器行为不一致。** Firefox 旧版本对同目录 `file://` 相对宽松，Chrome/Edge 默认更严格，
   于是出现"我这里能看、你那里打不开"的假象；用 http 才能保证所有浏览器一致。
3. **`localStorage` 不可靠。** 部分浏览器在 `file://` 下会禁用或隔离 localStorage，
   导致"标记掌握 / 已完成进度"无法保存（进度计数恒为 0）。
4. **本地服务器零依赖。** 本仓库无构建步骤、无第三方库，`http.server` 只是把文件按 MIME
   正确吐出来（尤其 `.js` 必须是 `text/javascript`，否则模块化校验会报 MIME 错误）。

**注意**：`tools/selftest.html` 使用 `../js/...` 相对路径加载脚本，因此**必须经由 http 访问**，
并且**必须保持 `tools/` 与 `js/` 的相对位置不变**（不要单独把 `selftest.html` 拷贝到别处）。

## 二、自动自检：`tools/selftest.html`

打开 <http://localhost:8000/tools/selftest.html>，页面会自动：

1. 与主程序**相同方式**加载 `js/data/manifest.js`、`js/math.js`、`js/illustrations.js`、`js/illustrations-data.js`
   （**刻意不加载 `app.js`**，避免其自动渲染主界面干扰检查并保证检查的是数据本身）；
2. 依次动态加载全部 **18 章 × 3 类 = 54 个**数据文件：
   `js/data/fig-N.js`、`js/data/k-N-<slug>.js`、`js/data/t-N-<slug>.js`
   （`slug` 取自 `DSHData.index[N].slug`，缺失时回退到 `DSHData.files[N].slug`）；
3. 加载失败**不中断**：记录 `onerror` 后继续加载其余文件，最后统一报告；
4. 运行全部校验项，页面顶部给出**通过 / 警告 / 失败**三色汇总与计数，
   下方按检查项分组、逐条列出明细（失败项默认展开，通过项折叠）；
5. 顶部提供「重新检测（重新加载）」按钮（等价于 `location.reload()`）与
   「打开首页」「基础知识第 1 章」两个便捷链接。

### 检查项清单（与页面「检查项对照表」一致）

| 编号 | 检查内容 | 失败含义 / 常见原因 |
| --- | --- | --- |
| **A** | 54 个数据文件是否都加载成功（记录 `onerror`） | 文件名拼错、slug 与 `manifest.js` 不一致、文件缺失、JS 语法错误、MIME 类型不对、用了 `file://` |
| **B** | 18 章都有 `registerKnowledge`；`id` 与章号一致、`name` 非空、`sections ≥ 4`、`proofs ≥ 2`（每条有 `title` 与 ≥ 2 个 `steps`） | 数据未注册、注册时写错 `id`、概念节数不足、证明只是复述结论 |
| **C** | 18 章都有 `registerTypes`；`types ≥ 3`；每个题型有 `name`、`questions`、`examples` | 题型数量不足、漏写 `examples`，或题型名称/顺序与大纲不一致 |
| **D** | 每个题型 `questions.length ∈ {3,4}`；同一题型内 `kind` 至少 2 种；`kind` 只能是 `choice`/`blank`/`short` | 只出选择题（题型方向单一）、`kind` 拼写错误（如 `single`） |
| **E** | 每题有非空 `stem`、`answer`、`answerText`（或 `answer` 数组）、`solution`（去 HTML 标签后 ≥ 15 字符，不得只写"略"） | 解析过短、漏写 `answerText`（副界面"答案速查"会显示"见解析"） |
| **F** | `choice` 必须有 4 个非空 `options` 且 `answer` ∈ {A,B,C,D}；`blank` 必须有非空 `blanks` 且每个 blank 有 `answer` | 选项不足 4 个、答案写成选项内容而非字母、填空没给判分答案 |
| **G** | 题目 `id` 形如 `N-M-K`、例题 `id` 形如 `N-M-ex-K`，且**整章内唯一**（含题目与例题混排查重） | 复制粘贴导致 id 重复 → 进度记录 (`localStorage`) 会串号、判分勾选错题 |
| **H** | 每个题型 `examples.length ∈ {1,2}`；每条例题有 `problem` 与 `solution` | 例题缺失或超过 2 条 |
| **I** | 所有 `DSHFig.use('x')` 与 `DSHFig.row([{id:'x'},…])` 引用的图 id 都存在于 `DSHFig.registry`；缺失时列出「章号 + 图 id」。另按 `docs/数据格式说明.md` 第七节核对各章**规范分配的简图 id** 是否注册 | 引用了不存在的图（页面会显示红色"未找到简图：x"）、`fig-N.js` 未加载或 `add()` 的 id 写错 |
| **J** | 全部字符串中 `\(` 与 `\)` 数量相等、`\[` 与 `\]` 数量相等；不等时报出章号与片段 | 公式漏写右括号 → 渲染器会把后面的正文一起吞进公式里 |
| **K** | `DSHData.order` 是否为 `1..18` 连续，`DSHData.index` 是否覆盖 18 章 | `manifest.js` 被改动或某章 `id` 写错导致顺序错乱、侧栏目录缺章 |
| **L** | 渲染冒烟：取每章第一个题型的第 1 题的 `stem` + `solution`，经 `DSHMath.render` 渲染到隐藏容器，检查是否产生 `<math>` 元素且无异常 | 渲染器抛错、公式写法超出 `docs/数据格式说明.md` 第三节支持的子集、或首题完全没有公式 |
| **M** | 附加项：全程控制台是否出现 `error` / `warning` | 数据文件自身的异常、重复注册（`DSHData` 会 `console.warn`）等 |

**结果怎么读**

- 绿色 **通过**：该项合规。
- 黄色 **警告**：不致命，但建议修（例如某章规范简图未注册、首题无公式、控制台 warning）。
- 红色 **失败**：必须修（文件没加载、数据缺失、公式不配对、id 重复等）。
- 失败项默认展开，`<pre>` 里是**逐条定位信息**（章号 / 题型 / 题号 / 文件路径 / 片段），
  按它直接去改对应文件即可。
- 页面底部还有「文件加载明细」与「环境信息」两张表，用来核对**实际请求的路径**是否正确。

### 当前进度提示（重要）

仓库目前只完成了部分数据文件。在只存在 `js/data/fig-10.js`、而 `k-*.js` / `t-*.js` 尚未写的情况下，
自检页会给出大量 **A/B/C/D–H/L 失败**——这是**预期的正确行为**，正说明自检页有效。
每写入一章（`fig-N.js` + `k-N-<slug>.js` + `t-N-<slug>.js`）后重新点「重新检测」，
失败数应当相应减少，直到全部转为**通过 / 无警告**。

### 4. 公式渲染（`DSHMath`）

## 四、常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 首页显示"数据文件缺失或加载失败" | 用了 `file://`，或文件没被服务器覆盖到 | 改用 http 打开；确认文件路径与 `manifest.js` 的 slug 一致 |
| 自检页 A 项大量 404 | `k-N-<slug>.js` / `t-N-<slug>.js` 文件名与 `manifest.js` 的 `slug` 不一致（中文文件名须完全一致） | 按 `DSHData.index[N].slug` 重命名文件 |
| 自检页 B/C 项"缺少 registerKnowledge/registerTypes 数据" | 文件加载成功但没调用注册函数，或 `id` 写成了字符串以外的值 | 检查 `DSHData.registerKnowledge({ id: N, ... })` |
| 页面上出现红色「未找到简图：x」 | `DSHFig.use` 引用的 id 没在 `fig-*.js` 里 `add` | 对齐 id，或补上该简图（自检 I 项会列出章号 + 图 id） |
| 公式后面的正文被吞进公式 / 显示成怪异排版 | `\(` 少了 `\)`（自检 J 项会定位） | 补齐配对符号；注意 `points` 等数组字符串里的反斜杠要写成 `\\` |
| 提交判分永远判错 | `answer` 写法与 `norm()` 归一化规则不匹配，或填空题漏写 `blanks[i].answer` | 参考 `app.js` 的 `norm`/`eqAnswer`，answer 用最规范的写法，或用数组给出等价写法 |
| 进度计数错乱 / 勾选到别的题 | 题目 `id` 重复（自检 G 项会报） | 修正重复 id，例如 `1-1-3` vs `1-2-3` |
| 侧栏目录缺章 / 顺序不对 | `DSHData.order` 被改动，或某章 `registerKnowledge` 的 `id` 与文件名不符 | 保持 `manifest.js` 的 `order = [1..18]`；核对 `id` |
